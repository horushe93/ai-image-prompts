# Plan: json-image 项目级 Skill

> 来源: demands.md ## Skill 生图
> 日期: 2026-05-15
> 状态: 已实施

## 方案摘要

创建一个项目级 Claude Code Skill（`json-image`），当用户提及「指定风格 × 指定宽高比」时，自动从 `example_cases.json` 提取所有 case 的 `environment_variables`，替换到 `prompt-template.json` 中，并发调用 image-gen（Replicate + GPT Image 2）生成全部预览图，按序号保存到对应 `preview/` 目录。

- [ ] Task 2: 创建辅助脚本 — JSON 变量替换与 prompt 组装 | files: `.claude/skills/json-image/scripts/assemble-prompt.ts` | complexity: 低 | depends_on: 无

## 架构决策

### 决策 1: Skill 形态 — 纯声明式 SKILL.md vs SKILL.md + 辅助脚本

**选择**: SKILL.md（声明式工作流描述）+ 轻量辅助脚本（JSON 合并）

**原因**:
- 核心编排逻辑（读取文件、并发调度、错误处理）由 Claude Code 在运行时执行，SKILL.md 提供精确指令
- JSON 深度合并逻辑复杂且对确定性要求高（不能丢字段），适合用一个小型 TypeScript/Node 脚本做，避免 LLM 手工拼 JSON 出错
- 不创建完整的 CLI 工具 — 项目已有的 image-gen 已提供 CLI 接口，重复建设无意义

### 决策 2: 风格名称匹配策略

**选择**: 两级匹配 — 精确目录名优先，回退到模糊关键词映射

**原因**:
- `styles/` 下的目录名是规范名（如 `404-Renaissance`），但用户可能说 "renaissance" 或 "404"
- 在 SKILL.md 中维护一个映射表（当前仅 2 个 style，手动维护成本极低）
- 未来 style 增多时可升级为自动 glob + 相似度匹配

### 决策 3: 并发生图策略

**选择**: 遵循 image-gen SKILL.md 规定的 probe-then-concurrent 模式

**原因**:
- image-gen SKILL.md 已有成熟的批量调用最佳实践（先 probe 1 张验证通路，再 `xargs -P 5` 并发）
- Replicate GPT Image 2 推荐并发 5-10，我们的 case 数量通常 3-6 个，全部并发即可
- 统一使用 `set -euo pipefail` 确保任何失败立即停止

### 决策 4: 图片序号命名

**选择**: `01.png`, `02.png`, `03.png` — 基于 `example_cases` 数组的 1-based 索引

**原因**:
- 与现有 preview 目录中的文件命名一致（已有 `01.jpeg`, `02.jpeg`, `03.jpeg`）
- 序号对应 `example_cases` 中的顺序，用户可追溯到具体 case

### 决策 5: aspect-ratio 格式化

**选择**: 用户输入 `9:16` 或 `16:9`，自动转换为 snake_case key `9_16` / `16_9`，同时保留原始格式 `9:16` 用于传给 image-gen 的 `--aspect-ratio` 参数

**原因**:
- `example_cases.json` 的 key 是 `example_cases_9_16`（snake_case）
- image-gen CLI 接受 `--aspect-ratio 9:16`（冒号格式）
- 两端格式不同，需要在 SKILL.md 中明确双向转换规则

### 决策 6: 临时 prompt 文件策略

**选择**: 将组装好的每个 prompt 写入临时 `.md` 文件，然后喂给 image-gen `--file`

**原因**:
- image-gen 的 `--file` 模式支持从 Markdown 提取 prompt（含 metadata table 可指定 channel/model/ratio）
- 避免命令行参数过长（JSON prompt 通常 3-6KB）
- 临时文件在生图完成后清理

## SKILL.md 核心设计（预览）

### 触发条件
```
用户提及: "batch generate" / "批量生图" / "生成预览图" / "generate previews" / "generate all images for"
+ 风格名（如 "404-Renaissance" / "renaissance" / "digital editorial collage"）
+ 宽高比（如 "9:16" / "16:9"）
```

### 工作流（6 步）

1. **解析输入** — 将风格名匹配到 `styles/` 子目录，将宽高比转为 snake_case key
2. **读取数据** — 读取 `prompt-template.json` 和 `example_cases.json`
3. **组装 prompt** — 对每个 case，将 `environment_variables` 深度合并到模板，写入临时 `.md` 文件
4. **Probe** — 先用第 1 个 case 跑单次 image-gen，验证通路
5. **并发** — probe 成功后，`xargs -P` 并发跑剩余 case
6. **收尾** — 清理临时文件，报告生成结果

### 风格映射表
```json
{
  "404-renaissance": "404-Renaissance",
  "renaissance": "404-Renaissance",
  "404": "404-Renaissance",
  "digital-editorial-collage": "digital-editorial-collage",
  "digital editorial collage": "digital-editorial-collage",
  "editorial collage": "digital-editorial-collage",
  "digital editorial": "digital-editorial-collage",
  "collage": "digital-editorial-collage"
}
```

## 验收标准

- [ ] 用户说 "batch generate renaissance at 9:16" 能正确触发 skill
- [ ] 正确读取 `styles/404-Renaissance/example_cases.json` 的 `example_cases_9_16` 数组
- [ ] 每个 case 的 `environment_variables` 完整替换到模板中（不丢字段、不多字段）
- [ ] 并发生成的图片数量与 case 数量一致
- [ ] 图片保存为 `styles/<style>/preview/<ratio>/01.png`, `02.png`...（png 格式）
- [ ] 使用 Replicate 通道 + GPT Image 2 模型（非 Gemini）
- [ ] 临时文件在流程结束后被清理
- [ ] 中间任何一步失败时，流程立即终止（fail-fast）
